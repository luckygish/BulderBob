# План: единая локализация вместо двух версий

Статус: зафиксирован 2026-10-30. Цель — поддержка русского и английского из одного дерева кода, без ручного переключения веток.

## 1. Текущее состояние

- ~5180 строк TS в 31 файле; ~3090 EN-литералов, из них 145 строк на русском уже вшиты прямо в код (`catalog.ts`, `events.ts`, `engine.ts`, все UI-страницы).
- Формат — чистый TypeScript + Vite, без i18n-слоя. Две версии поддерживаются ручным переключением веток/коммитов — это и есть источник проблемы.
- Tauri-конфиг один (`productName: "Bulder"`), RU/EN exe собираются из разных состояний дерева.

## 2. Целевая архитектура

Одно дерево кода, строки — внешние ресурсы, выбор языка на старте:

```
web/src/i18n/
  index.ts        # загрузка dict, t(), форматтеры чисел/денег/дат
  ru.ts           # русский словарь (из текущего RU-кода)
  en.ts           # английский словарь (из текущего EN-кода)
  types.ts        # тип всех ключей (говорящий код без опечаток)
```

## 3. Шаги реализации

### Шаг 0. Подготовка (без рисков)
1. Зафиксировать текущий EN-рабочее дерево в отдельную ветку (эталон для `en.ts`).
2. Выкатить RU-контент (`web-ru-fix`, коммит `5267e7c`) как второй эталон для `ru.ts`.
3. Собрать **полный реестр строк** — все литералы с местоположением (`file:line`) из обеих версий. Разобрать: где текст, где числа (`toLocaleString`), где имена данных (`EFFECT_KEYS`, id).

### Шаг 1. Словари
4. Создать `i18n/types.ts` и `index.ts` с `t(key, params)` и форматтерами `money/number/date` под локаль (`ru-RU` / `en-US`, символ ₽/$).
5. Сгенерировать `ru.ts` из RU-версии и `en.ts` из EN-версии: тип ключей — заглушки-кода, значения — текст. Группы: `ui.*`, `game.*` (журнал, тосты, сообщения действий), `data.*` (названия построек/материалов/навыков/событий/технологий).

### Шаг 2. Прошивка кода (ядро)
6. `catalog.ts`, `events.ts`, `seasons.ts`, `progression.ts` — названия и тексты заменить на `data`-ключи; id и чистые поля оставить машинными.
7. `engine.ts`, `actions.ts` — все сообщения `message:` и `addLog` заменить на `t('...')`; числа форматировать через i18n-форматтеры вместо `toLocaleString('en-US')`.
8. `selectors.ts`, `persistence.ts` — статусы, прогнозы, миграции.
9. UI: `app.ts`, `components.ts`, все `pages/*` — шаблонные строки на `t()`. `money()` из `components.ts` переходит на i18n-форматтер.

### Шаг 3. Выбор языка и сборка
10. Автоопределение: `navigator.language` → кнопка переключения РУ/EN в меню; выбор сохраняется в `localStorage` (отдельно от сейва игры).
11. Tauri: параметр сборки (env/профиль) для exe-имени `Bulder`/`Bulder_EN`; одна кодовые база, два артефакта.

### Шаг 4. Тесты
12. Тесты переходят с поиска текста на ключи/локаль; в существующих `*.test.ts` заменить русские/английские литералы, параметризовать локалью.
13. Добавить тест: **все ключи `en.ts` = `ru.ts`** (нет пропусков) — страховка от рассинхрона.
14. Обновить `FORMULAS.md`/`README.md`, пересобрать `dist` и exe.

## 4. Порядок и риски

| Этап | Риск | Митигация |
|---|---|---|
| Генерация словарей | потерянные/дублирующиеся строки | совместить реестры RU и EN до генерации |
| Замена в `game/*` | сломанные тосты/журнал | тесты гоняются на каждом шаге |
| Замена в UI | визуальные артефакты (длина строк) | ручная проверка в обеих локалях |
| Миграция сейвов | тексты в `journal` старых сейвов | журнал хранит `{key, params}` вместо текста |

**Ключевое решение:** журнал сейчас пишет текст в сейв. Перенести на `{key, params}` — тогда старые сейвы показываются на языке сессии, а не замороженном. Меняет `persistence.ts` и формат (bump версии сейва).

## 5. Быстрые выигрыши

- `money/number/date` форматтеры — одна точка для локали.
- `t()` для 145 русских строк (это половина UI-текста) — мгновенная двуязычность без перевода данных.

Оценка: ~3–5 итераций кода + 1 на тесты. Начинать с Шага 0–1 (реестры и словари), не трогая логику.
