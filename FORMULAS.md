# Формулы и механики браузерной версии «Булдер»

Актуальный источник — TypeScript-код в `web/src/game/`. Ниже описаны механики версии
сохранения 2; старые формулы Godot-версии сохранены только как историческая основа.

Основные файлы: `balance.ts`, `catalog.ts`, `engine.ts`, `actions.ts`, `selectors.ts`.

---

## 1. Время

- Игровой тик — **1 час**.
- Рабочее время: `8 ≤ hour < 18`.
- При `hour = 24` день увеличивается, выполняются поставки, ежедневные платежи,
  ход ботов, исследования и обновление доски заказов.
- Реальный интервал тика, мс: ×1 — **2000**, ×2 — **1000**, ×4 — **250**.

Ночью объект не строится, если нет глобальной «Автоматизации» и хотя бы у одного работника
назначенных бригад нет навыка «Сова».

---

## 2. Рабочие и эффективность

### 2.1 Типы

| Тип | Базовая эффективность | Ставка, ₽/ч |
| --- | ---: | ---: |
| Разнорабочий | 0.8 | 800–1200 |
| Специалист | 1.0 | 1200–1600 |
| Прораб | 1.1 | 1800–2300 |

Командный бонус прораба — **+0.2** на каждого другого члена бригады.

### 2.2 Навыки

У работника **1–2 навыка**. Прораб не получает негативные навыки. Навыки одной группы
не сочетаются: скорость (`Алкоголизм`, `Трудяга`, `Медлительный`) и материалы
(`Вор`, `Бережливый`).

| Навык | Эффект |
| --- | --- |
| Алкоголизм | `speed −0.15` |
| Медлительный | `speed −0.10` |
| Трудяга | `speed +0.20` |
| Сова | разрешает ночную работу |
| Вор | `materialRate +0.05` |
| Бережливый | `materialRate −0.04` |
| Наставник | `teamBonus +0.06` на остальных |
| Логист | `logisticsRate −0.05` |
| Технолог | `equipmentBonusRate +0.15` |
| Дорогой специалист | `wageRate +0.15` |

### 2.3 Эффективность бригады

```
speed(w) = max(0.1, 1 + Σ speed_навыков)
base(w)  = efficiency_типа + workerBonus
bonus    = 0 / 0.2 / 0.4 после технологий персонала

eff = Σ base(w) · speed(w)
    + Σ [teamBonus_типа(w) + Σ teamBonus_навыков(w)] · (размер_бригады − 1)
```

Для проекта с несколькими бригадами рабочие всех назначенных бригад объединяются.

### 2.4 Зарплата

```
hourly = Σ round(rate(w) · (1 + Σ wageRate_навыков))
nightHourly = hourly · 1.5
```

`laborCost` увеличивается каждый фактический рабочий час проекта. Начисленная, но не выплаченная
зарплата списывается в конце игрового дня; нехватка денег превращается в `debt`.

## 3. Материалы, склады и резервы

### 3.1 Рынок

Каждый материал имеет лотовую FIFO-очередь на двух базах. Покупка списывает сначала самые
ранние лоты. Рынок пересчитывается раз в **3 дня**:

```
expected = dailyDemand · 3
ratio = demand_за_период / expected
price = round(basePrice · clamp(1 + 0.25 · (ratio − 1), 0.8, 1.35))
qty   = max(stockMin, round(expected · clamp(ratio, 0.25, 4)))
```

Лот старше 9 дней, от которого продано менее 40%, уценяется на 5% до минимума 80% базовой цены.

### 3.2 Два склада

- `state.inventory` — общий склад компании.
- `project.reserved[material]` — партии, зарезервированные конкретным объектом.

Быстрая закупка для проекта:

```
need = max(0, required − allocated_on_stages − project_reserved − common_inventory)
```

После покупки партия сразу попадает в резерв проекта. Отложенная поставка также прибывает в его
резерв. Другой проект не считает эти материалы доступными.

### 3.3 Обеспечение этапа

Сначала расходуется резерв проекта по фактической себестоимости партий, затем общий склад:

```
materialCost += takenCost · max(0.85, 1 + Σ materialRate_навыков_бригад)
```

Остаток резерва после сдачи объекта возвращается на общий склад по прежней себестоимости.

## 4. Техника и этапы

Каждая единица техники — экземпляр с уникальным `assetId`. На объект назначается конкретный
экземпляр.

### 4.1 Обязательная техника

Этап имеет `requiredEquipment`, только если техника обязательна. Для обычного фундамента:

```
requiredEquipment = [mixer, tractor, excavator]
```

Для отдельных этапов особых проектов — только указанная спецтехника, например `crane`.
Если текущий этап не имеет требования, назначение техники не нужно для продолжения стройки.

### 4.2 Бонус техники

У этапа есть карта `equipmentBonus`:

| Техника | Фундамент | Стены/монтаж | Кровля | Отделка |
| --- | ---: | ---: | ---: | ---: |
| Бетономешалка | 0 | 0 | 0 | 0 |
| Трактор | +0.30 | 0 | 0 | 0 |
| Экскаватор | +0.45 | 0 | 0 | 0 |
| Манипулятор | 0 | +0.15 | 0 | +0.10 |
| Кран | 0 | +0.10 | +0.20 | 0 |

```
equipmentBonus = baseBonus · (1 + Σ equipmentBonusRate_навыков)
progressPerHour = crewEfficiency · (1 + equipmentBonus) / manHoursStage
```

### 4.3 Стоимость техники

- Покупка: полная цена.
- Аренда: `hours · rentPerHour`, минимум 8 часов; час списывается только за фактический час
  работы на объекте.
- Лизинг: взнос `20%`, полная сумма `price · 1.12`, ежедневный платёж за 30 дней.
- Обслуживание своей и лизинговой единицы: `round(price · 0.001)` в день.

---

## 5. Обеспечение площадки

Для каждой позиции обеспечения:

```
owned_count ≥ active_projects_count
```

Не хватает одной бытовки, биотуалета, канистры, генератора или ручного инструмента — запуск
этапа невозможен. После удаления сданного проекта из списка активных его комплект освобождается.

---

## 6. Строительство

### 6.1 Условия запуска этапа

1. Нет текущего долга.
2. Назначено требуемое число непустых бригад: обычно 1, особые проекты — 2.
3. Для текущего этапа назначена подходящая обязательная техника, если она требуется.
4. Выполнено условие обеспечения для всех активных объектов.
5. На этапе есть все материалы.

### 6.2 Прогресс и сдача

```
stageProgress += crewEfficiency · (1 + equipmentBonus) / manHoursStage
```

Завершение последнего этапа сразу формирует финансовый результат:

```
profit = budget − materialCost − laborCost − logisticsCost
       − equipmentCost − factoringFee − penalty

penalty = round(budget · min(0.15, lateDays · 0.03))
reputation += lateDays > 0 ? (−5 − lateDays) : building.reputationReward
```

Для обычных объектов награда репутации — +2; «Ангар» — +8; «Телевышка» — +10.

## 7. Заказы и особые проекты

### 7.1 Обычные заказы

- На доске поддерживается 3–5 заказов.
- Обычный заказ исчезает, когда до срока сдачи осталось менее 2 дней.
- Каждый день добавляется 1–2 новых заказа.
- Лимит активных проектов: 1 → 2 → 3 → 4 по технологиям планирования.

### 7.2 Особые заказы

В дни, кратные 3:

```
P(особый заказ) = 0.10, если на доске нет другого особого и есть место
```

- Тип выбирается случайно из `hangar` и `tv_tower`.
- Время на доске: **2–5 дней**.
- Требуют две бригады и спецтехнику на отдельных этапах.
- Боты их игнорируют.

---

## 8. Финансы

### 8.1 Платежи и долг

Ежедневно списываются:

1. накопленная зарплата активных проектов;
2. платёж по кредиту;
3. лизинговые платежи;
4. обслуживание техники.

Если денег недостаточно:

```
paid = min(money, obligation)
money -= paid
debt += obligation − paid
```

При положительном `debt` новые расходы, покупки, исследования и строительство заблокированы.
Свободные деньги автоматически погашают долг.

### 8.2 Кредиты

```
total = amount · (1 + rate)
daily = round(total / 30)
```

- 500 000 ₽ под 6%.
- 800 000 ₽ под 8%.
- Одновременно один кредит, доступ после «Банковского счёта».

### 8.3 Факторинг

После исследования при взятии заказа:

```
advance = round(budget · 0.30)
fee     = round(budget · 0.02)
money  += advance − fee
```

Финальный платёж уменьшается на аванс.

## 9. Конкуренты

Боты используют общий рынок, общий пул кандидатов и общую доску заказов, но не берут особые
проекты. Оценка заказа:

```
materials = Σ frontPrice(material) · qty
labor     = manHours · 1400
margin    = budget − materials − labor
```

Заказ выбирается по:

```
score = margin / budget
      + (агрессивная стратегия ? budget / 4_000_000 : 0)
      − (консервативная стратегия ? manHours / 500 : 0)
```

Бот покупает материалы по фактической FIFO-стоимости и ежедневно оплачивает:

```
wages  = hourly(crew) · 10
rental = 35 000
```

После сдачи бот возвращает рабочих в общий пул и находится в паузе 2–4 дня.

---

## 10. Капитал и цель сезона

```
capital = money
        + Σ price(техники со статусом owned/leased)
        − debt − remainingLoan
```

Цель: за первые 90 дней достичь капитала **10 000 000 ₽** и репутации **70**.
После достижения цели можно продолжать игру.
